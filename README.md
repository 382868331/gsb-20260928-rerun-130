# 构建依赖执行引擎

一个基于内容寻址的 Go 增量构建引擎。构建被建模为一组**动作（Action）**，每个动作声明工具、参数、输入文件与产物文件；动作之间的依赖由输入/产物路径关系自动推导，构成有向无环图（DAG）。

## 依赖模型

- **任务/输入/产物关系建图**：产物路径 → 生产者动作的映射推导依赖边，共享前置（如菱形依赖的公共节点）在拓扑序中只执行一次，环会被拒绝。
- **受控动作**：引擎只执行通过 RegisterTool 注册的工具，新工具实现 engine.Tool 接口即可接入同一依赖模型；不做仓库自动发现、不启用仓库自动构建。
- **内容定重建**：动作指纹 = 工具名 + 排序后的参数 + 每个输入文件内容的 SHA-256，不看时间戳。产物还会记录内容哈希，磁盘上被外部改坏或删除的产物会被识别并定点重建。
- **原子发布**：动作在临时暂存目录中产出，全部产物就绪后才 rename 到目标位置；失败不会发布半个产物，也不会污染已记录的状态。
- **重启恢复**：每个动作完成后状态即时落盘（.buildstate.json，原子写），新进程打开同一目录即可继续增量构建。

## 用法

    e, _ := engine.New(root)
    e.RegisterTool("copy", engine.ToolFunc(tools.Copy))
    e.RegisterTool("upper", engine.ToolFunc(tools.Upper))
    e.RegisterTool("concat", engine.ToolFunc(tools.Concat))

    e.AddAction(engine.Action{ID: "gen", Tool: "copy",
        Inputs: []string{"src.txt"}, Outputs: []string{"gen/a.txt"}})
    // ... 更多动作，依赖由 Inputs/Outputs 自动连接
    err := e.Build("merge") // 只重跑输入/参数/产物发生变化的动作

## 构建结果视图与来源说明

- **来源说明（Provenance）**：每个动作记录工具、参数、每个输入的内容哈希及其来源（源文件或上游动作）、产物哈希。使用者可据此判断产物是否对应自己要求的源码与依赖状态。
- **可保存视图**：`BuildView(ctx, name, targets...)` 把一次构建的完整记录（实际参与的输入、每个动作的状态、失败原因、未完成部分）原子保存到 `.views/<name>.json`。视图不可变：同名再次请求返回 `ErrViewExists`，后来的源码变化不会悄悄替换已保存的记录；`LoadView(name)` 读回。
- **部分失败与取消续跑**：BuildView 不因单个动作失败而中止，独立分支继续执行，失败动作的下游标记为 skipped；ctx 取消时剩余动作标记为 canceled 且视图照常落盘。重开新视图即可从已落盘状态续跑，已完成动作标记为 reused。
- **依赖途中漂移**：动作执行期间输入发生变化时，该动作标记为 drifted，刚记录的状态被丢弃——产物明确不属于本视图，下次构建必须重做。
- **可解释的复用**：`Explain(actionID)` 对比记录状态与当前工作区，逐项说明产物为何可复用，或哪个输入/参数/产物发生了变化；`DiffViews(a, b)` 报告两个视图之间哪些输入变化真正导致了产物差异。

## 实验候选

`NewExperiment("cand-a", "cand-b")` 从当前已知状态为每个候选快照出独立工作区（含构建状态），两组修改互不干扰，缓存不会串用。`CompareCandidates(a, b)` 按内容哈希比较两边产物；`Adopt(name)` 把某个候选的产物与状态写回基础工作区，其余候选目录（含失败依据）原样保留，`Cleanup()` 显式清除。
